# Целевой грейд и задания на кодинг

Перед комплексным тестом кандидат выбирает Junior, Middle или Senior (при записи и перед стартом). После старта выбор фиксируется в попытке. Обычные навыки остаются без выбора грейда. Состав адаптивных частей не упрощается при выборе более низкого грейда: целевой уровень определяет трактовку результата.

Результат роли вычисляется после всех модулей и интеграционного блока:

- Выбранный грейд и следующий достигнуты: **выбранный грейд+ подтверждён · потенциал следующего**.
- Выбранный грейд и его «+» достигнуты, следующий не достигнут: **грейд+ подтверждён**.
- Выбранный грейд достигнут без «+»: **грейд подтверждён**.
- Выбранный грейд не достигнут, нижний достигнут: **выбранный не подтверждён · подтверждён нижний грейд**, с «+», если достигнут и его порог.
- Даже Junior не достигнут во всех модулях: **выбранный грейд не подтверждён**, без присвоения нижнего.

Порог «+» для каждого модуля — середина между порогами грейда и следующего. Для Senior — середина между порогом Senior и 100. При порогах 50/70/90 это Junior+ 60, Middle+ 80, Senior+ 95. Каждый обязательный модуль и интеграционный модуль должны выполнить соответствующее требование. Высокий балл в другой области не компенсирует недостаточный. Потенциал следующего показывается только при фактическом достижении всех его порогов.

Правило `target-grade-five-outcomes-midpoint-v2` фиксируется при старте. Пороги и основание «+» сохраняются в результате. Старые попытки без этого правила сохраняют прежний отчёт. Действующая политика обновления основной категории резюме сохраняется; пять исходов видны в карточках ролевых тестов и разделе результатов.

В рабочий банк добавлены задания формата `coding` для 18 модулей. У каждого сохранены язык, начальный код, открытые и скрытые проверки и время. Администратор может добавлять такие задания и менять количество практических заданий (0–3) и время (60–3600 секунд) в новой версии спецификации. Кодинг добавляется после двух адаптивных частей, сохраняя 32 основных вопроса. Он оценивается по всем проверкам как правильный/неправильный с тем же весом сложности; знаменатель шкалы учитывает добавленный объём. Старые пулы не меняются.

Редактор поддерживает Tab для отступов и Ctrl/⌘+Enter для запуска открытых примеров, автосохранение в попытке и отдельный таймер. Закрытые проверки и их ключи не отправляются клиенту. Кнопка «Ответить» проверяет всё на сервере. По истечении времени проверяется последнее сохранённое решение. Подделать правильность ответом клиента нельзя. LLM не оценивает решения.

Песочница доступна по `/sandbox` с примерами. Языки: Python, JavaScript, TypeScript, PostgreSQL SQL, Bash, HTML, CSS и React/TSX. Для статистики/ML используется Python; установленная среда содержит стандартную библиотеку. HTML/CSS/React могут показываться в iframe без скриптов и сети. Для новых HTML/CSS-заданий мейнтейнер может задать проверяемые фрагменты результата `contains`; это простая структурная проверка, а не проверка дизайна в браузере.

## Локальный запуск

```sh
docker build -t fsp-code-sandbox:local sandbox
npm run dev -- --hostname 127.0.0.1 --port 4173
```

Для создания нового опубликованного дня со всеми модулями, по одному практическому заданию на модуль и 10 минутами на кодинг:

```sh
node --env-file=.env.local scripts/prepare-coding-session.mjs
```

Скрипт создаёт новую сессию на 48 часов и новые версии спецификаций; ранее опубликованные сессии и попытки не меняет. Не запускать повторно, если новая сессия не нужна.

## Изоляция и размещение

Код выполняется только в отдельных Docker-контейнерах: без сети, host mounts и дополнительных capabilities, с read-only rootfs, непривилегированным UID, ограничениями CPU, памяти, процессов, времени и вывода. Данные теста идут через stdin; ожидаемый результат остаётся в контролирующем сервисе. Образы заранее собираются, на каждый запуск их скачивание запрещено. При отсутствии Docker выполнение возвращает понятную ошибку и не заменяется запуском на хосте.

В production web-контейнеру не следует выдавать Docker socket. На выделенном Docker-хосте запустите `scripts/code-sandbox-server.mjs`, задав `CODE_SANDBOX_TOKEN` (минимум 32 символа), `CODE_SANDBOX_HOST` и `CODE_SANDBOX_PORT` (по умолчанию 4180, 127.0.0.1). У web-приложения задайте `CODE_SANDBOX_URL` и тот же `CODE_SANDBOX_TOKEN`. Сервис должен оставаться в приватной сети; при переходе между хостами использовать HTTPS. Docker сам по себе не заменяет изоляцию отдельного хоста для публичного выполнения недоверенного кода.

```sh
CODE_SANDBOX_TESTS=1 node --test tests/code-runner.test.mjs tests/assessments.test.mjs
```
