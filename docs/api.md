# Публичный API ФСП Карьеры

Базовый адрес: `https://fspcareer.space/api/v1`. Формат: JSON, UTF-8. [Документация на сайте](https://fspcareer.space/api-docs), [OpenAPI 3.1](https://fspcareer.space/api-v1.openapi.json). Публичный API использует собственные ключи; `/api/state`, `/api/action` и `/api/session` остаются внутренним интерфейсом браузерного кабинета.

## Получить ключ

Войдите с подтверждённым email, откройте свой кабинет → **API-ключи** → **Создать ключ**. Выберите чтение или чтение и запись, срок 30 или 90 дней. Полный ключ показывается один раз; сохраните его в секретах своего приложения. Можно иметь до 10 действующих ключей. Список в кабинете показывает название, начало ключа, права, срок и последнее использование. Отзыв действует для следующих запросов; уже выполняющийся запрос может завершиться. Смена/восстановление пароля отзывает все ключи.

Ключ действует от имени аккаунта и сохраняет его роли. Для поиска кандидатов нужен созданный профиль компании. Наличие ключа не открывает чужие кабинеты, скрытые профили, скрытые результаты тестов или закрытые контакты. Если аккаунт имеет обе роли, для списков кабинета передавайте `role=employer` или `role=candidate`.

Во всех запросах передавайте `Authorization: Bearer <ключ>`. Cookie не заменяет ключ, ключ в query string не принимается. Запросы записи требуют `Content-Type: application/json`. Для серверного API заголовок `Origin` не нужен. Используйте HTTPS и серверные интеграции; CORS для сторонних браузерных приложений не включён.

```bash
read -rs -p 'API key: ' FSP_API_KEY; echo
export FSP_API_KEY
FSP_API_URL=https://fspcareer.space/api/v1

curl --fail-with-body "$FSP_API_URL/me" \
  -H "Authorization: Bearer $FSP_API_KEY"
```

Успех возвращает `{ "data": ... }`, списки дополнительно содержат `pagination`. Все ответы имеют `Cache-Control: no-store` и `X-Request-ID`. Временные метки — миллисекунды Unix, деньги — рубли в месяц. Демонстрационные записи имеют `synthetic: true`; это тестовые люди/вакансии, реальные пользователи за ними не стоят.

## Поиск кандидатов

```bash
curl --fail-with-body --get "$FSP_API_URL/candidates" \
  -H "Authorization: Bearer $FSP_API_KEY" \
  --data-urlencode 'query=Middle backend Python PostgreSQL' \
  --data-urlencode 'spec=Backend' \
  --data-urlencode 'grade=Middle' \
  --data-urlencode 'stack=Python,PostgreSQL' \
  --data-urlencode 'format=Удалённо' \
  --data-urlencode 'budgetMax=250000' \
  --data-urlencode 'limit=20' \
  --data-urlencode 'offset=0'
```

Специализация и грейд, заданные явно, подтверждают категорию для ранжирования. Если передан только свободный `query`, API разбирает потребность и возвращает `need`, но выдача остаётся пустой до `confirmed=true` или явных `spec` и `grade`. Если специализация или грейд не определились, уточните их; подтверждение не подставляет значения по умолчанию. Без `query` каталог можно фильтровать сразу. Неизвестные, повторяющиеся и некорректные параметры возвращают 400.

| Параметр | Значения и смысл |
|---|---|
| `query` | Потребность свободным текстом, до 2000 символов. Влияет на разбор и ранжирование; не является поиском по имени |
| `spec` | `Backend`, `Frontend`, `Data Science`, `ML Engineering`, `DevOps`, `QA`; точный фильтр |
| `grade` | `Junior`, `Middle`, `Senior`; точный фильтр |
| `stack` | До 20 технологий через запятую, все должны присутствовать; регистр не важен, известные алиасы нормализуются |
| `city` | Подстрока города без учёта регистра, до 80 символов |
| `format` | `Удалённо`, `Гибрид`, `Офис` |
| `salaryMin`, `salaryMax` | Целые 1–10000000. Диапазон кандидата должен пересекаться с указанным; неизвестная зарплата исключается |
| `minScore` | Минимальный результат подтверждённого теста, 0–100; не балл соответствия потребности |
| `fsp` | `all` (по умолчанию), `with` — есть видимые достижения, `without` — нет видимых достижений |
| `synthetic` | `true` — только демопрофили, `false` — только реальные; без параметра — оба вида |
| `favorites` | `true` — только ваше избранное, `false` — без избранного |
| `sort` | `match` (порядок сайта: категории, соответствие, сила профиля), `strength`, `score`, `salary` (сначала дешевле), `name` |
| `team` | Контекст команды, до 2000 символов; влияет на ранжирование вместе с `query` |
| `budgetMin`, `budgetMax` | Целые 1–10000000; бюджет потребности влияет на балл соответствия, но не является жёстким фильтром. Для фильтра используйте `salaryMin`/`salaryMax` |
| `confirmed` | `true` — подтвердить разобранную категорию; `false` — оставить неподтверждённой, если не заданы оба `spec`/`grade` |
| `limit`, `offset` | Размер страницы 1–100 (по умолчанию 20); смещение 0–100000 (по умолчанию 0) |

Ответ:

```json
{
  "data": [
    {
      "id": "candidate-id",
      "name": "Имя кандидата",
      "spec": "Backend",
      "grade": "Middle",
      "stack": ["Python", "PostgreSQL"],
      "synthetic": true,
      "score": 91,
      "min": 180000,
      "max": 240000,
      "match": {"score": 87, "strength": 26, "parts": [], "reasons": []}
    }
  ],
  "pagination": {"total": 12, "limit": 20, "offset": 0, "nextOffset": null},
  "need": {"spec": "Backend", "grade": "Middle", "confirmed": true},
  "categories": []
}
```

Это сокращённый пример структуры. Реальный `match.parts` содержит объяснение всех слагаемых балла, `categories` — рекомендации категорий. Сила профиля и соответствие — разные показатели. Модель ранжирования остаётся правилами MVP, не гарантией качества найма. `grade`, `score`, `verifiedAt` могут отсутствовать/быть `null`, если подтверждение скрыто кандидатом. Скрытые результаты не возвращаются и не участвуют в балле.

Следующую страницу запрашивайте с `offset=pagination.nextOffset`, пока значение не станет `null`. Каталог может измениться между запросами; offset-пагинация не даёт фиксированного снимка. `GET /candidates/{id}` возвращает видимый профиль; скрытый или неизвестный ID — 404. Email/телефон отсутствуют до принятия приглашения этой компании или отклика кандидата на её вакансию. Достижения ФСП учитывают настройку их видимости.

## Методы

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/me` | Собственный аккаунт, роли, профиль, компания, приватность |
| GET | `/taxonomy` | Текущие специализации, грейды, форматы, разрешённые операции, лимиты |
| GET | `/candidates` | Поиск работодателя с фильтрами и пагинацией |
| GET | `/candidates/{id}` | Профиль видимого кандидата |
| GET | `/jobs`, `/jobs/{id}` | Опубликованные вакансии и публичная информация компании |
| GET | `/needs` | Ваши сохранённые подборки; требуется профиль компании |
| GET | `/favorites` | ID кандидатов в вашем избранном; требуется профиль компании |
| PUT / DELETE | `/favorites/{candidateId}` | Добавить/убрать избранное; повторные запросы безопасны |
| GET / POST | `/invites` | Ваши приглашения / отправить предложение кандидату |
| GET | `/applications` | Отклики своего кабинета |
| GET | `/messages` | Доступные вам сообщения |
| GET | `/tasks` | Опубликованные задания и ваши собственные |
| GET | `/submissions` | Решения заданий своего кабинета |
| GET | `/state` | Полное собственное представление кабинета; без пагинации, как на сайте |
| POST | `/actions` | Разрешённая операция кабинета, описанная ниже |

`/jobs` принимает `query` (подстрока названия/описания/компании/стека), `spec`, `grade`, `stack`, `city`, `format`, `salaryMin`, `salaryMax`, `synthetic`, `limit`, `offset`. Результат — новые вакансии сначала. Для `needs`, `favorites`, `invites`, `applications`, `messages`, `tasks`, `submissions` доступны `role`, `limit`, `offset`, `status`, `contextId`; последние два фильтруют поля записи, когда они есть. Для `/state` `role` выбирает роль; полный ответ содержит свои результаты тестов в проекции владельца, но не вопросы/ключи ответов чужих попыток.

### Избранное

```bash
curl --fail-with-body -X PUT "$FSP_API_URL/favorites/CANDIDATE_ID" \
  -H "Authorization: Bearer $FSP_API_KEY"
```

Ответ: `{ "data": { "candidateId": "CANDIDATE_ID", "saved": true } }`. DELETE возвращает `saved: false`. Добавить скрытого или неизвестного кандидата нельзя; удалить прежнее избранное можно и после скрытия профиля.

### Отправить приглашение

Нужен ключ с записью и профиль компании. Подставьте ID из выдачи и свой контакт.

```bash
curl --fail-with-body -X POST "$FSP_API_URL/invites" \
  -H "Authorization: Bearer $FSP_API_KEY" \
  -H 'Content-Type: application/json' \
  --data '{"candidateId":"CANDIDATE_ID","title":"Backend-разработчик","description":"Предлагаем обсудить работу над нашим продуктом.","contact":"hr@example.com","min":180000,"max":250000}'
```

Запрос содержит `candidateId`, `title` (до 160 символов), `description` (до 5000), `contact` (до 160), `min`, `max` — оба положительные целые, верхняя граница не ниже нижней. Ответ `data` содержит `message` и созданный `record` с ID. Повторное открытое приглашение той же компании тому же кандидату — 409. Приглашение демопрофилю сохраняется с отметкой `synthetic`, но человек на него не ответит.

### Другие операции кабинета

`POST /actions` вызывает те же бизнес-правила и проверки владельца, что сайт. Ключ с чтением не может их вызвать. Верхний предел JSON — 30000 байт, для `company` — 60000. Полный список действий также возвращает `/taxonomy`. Не отправляйте тело GET-запроса.

| `action` | Основные поля |
|---|---|
| `onboard` | `role`, `consent: true`; кандидат: `name`, `city`; компания: `name`, `city`, `description`, `contact` |
| `profile` | Собственный профиль кандидата: `name`, `city`, `about`, `stack`, `format`, `min`, `max`, `phone`, `education`, `work`; можно передать структурированный `resume` |
| `resume-details` | Структурированные `headline`, `languages`, `achievements`, `links`, `skillGroups`, `projects`, `workEntries`, `educationEntries` |
| `survey` | Анкета кандидата; схема полей — в существующем [OpenAPI кабинета](https://fspcareer.space/openapi.json) |
| `settings` | Кандидат: `visible`, `consent`, `notifications`, `fspVisible` — boolean. Для сохранения передавайте все настройки |
| `company` | Профиль компании; схема полей — в OpenAPI кабинета |
| `fsp-link`, `fsp-unlink` | Тестовая привязка: `fspId` (`DEMO-FSP-001`–`014`) / удаление; реальный реестр не подключён |
| `need` | `text`, `title`, `spec`, `grade`, `stack`, `confirmed: true`, `team`, `format`, `city`, `budgetMin`, `budgetMax` |
| `delete-need` | `id` собственной подборки |
| `favorite` | `candidateId`; переключает состояние. Для повторяемых интеграций предпочитайте PUT/DELETE `/favorites/{id}` |
| `invite` | Поля как у POST `/invites` |
| `invite-status` | Кандидат: `id`, `status` = `viewed` / `accepted` / `declined`; решение терминально |
| `job` | Компания: `title`, `description`, `spec`, `grade`, `stack` (строка через запятую), `format`, `city`, `min`, `max`; `id` — для редактирования своей вакансии |
| `job-status` | Компания: `id`, `status` = `published` / `archived` |
| `apply` | Кандидат: `jobId`, `letter` |
| `application-status` | Компания: `id`, `status` = `viewed` / `shortlisted` / `rejected`, `feedback` |
| `message` | `contextId` — ID доступного приглашения/отклика, `text` до 4000 символов; приглашение сначала нужно принять |
| `task` | Компания: `title`, `description`, `spec` |
| `task-answer` | Кандидат: `id` задания, `answer` от 30 до 8000 символов |
| `task-review` | Компания: `id` решения, `feedback` до 3000 символов |

Пример сохранения подборки:

```bash
curl --fail-with-body -X POST "$FSP_API_URL/actions" \
  -H "Authorization: Bearer $FSP_API_KEY" \
  -H 'Content-Type: application/json' \
  --data '{"action":"need","title":"Python-команда","text":"Middle backend Python","spec":"Backend","grade":"Middle","stack":"Python,PostgreSQL","confirmed":true,"format":"Удалённо","budgetMax":250000}'
```

Ответ: `{ "data": { "message": "...", "record": { "id": "...", "kind": "need", "...": "..." } } }`. `record` присутствует, когда операция сохраняет запись; изменения аккаунта возвращают сообщение, актуальные поля можно получить через `/me`. Операции тестирования (`assessment-*`, `test-*`), администрирования (`maintainer-*`) и управления ключами недоступны через `/actions`. Управление ключами — только из браузерной сессии в ЛК.

## Ошибки и лимиты

```json
{"error":{"code":"FORBIDDEN","message":"У ключа нет права записи."},"requestId":"..."}
```

| HTTP | Код | Что делать |
|---|---|---|
| 400 | `BAD_REQUEST` | Исправить параметры, JSON или действие |
| 401 | `UNAUTHORIZED` | Проверить Bearer-ключ, срок и отзыв; после смены пароля создать новый |
| 403 | `FORBIDDEN` | Проверить роль аккаунта и право записи |
| 404 | `NOT_FOUND` | Проверить адрес, метод и ID; запись может быть скрыта или чужая |
| 409 | `CONFLICT` | Обновить состояние: дубликат приглашения, уже принятое решение и т. п. |
| 413 / 415 | `PAYLOAD_TOO_LARGE` / `UNSUPPORTED_MEDIA_TYPE` | Уменьшить JSON / задать `Content-Type: application/json` |
| 429 | `RATE_LIMITED` | Подождать `Retry-After` секунд (60), затем повторить |
| 500 | `INTERNAL_ERROR` | Сохранить `requestId` для диагностики; для записи сначала проверить, сохранилось ли действие |

Лимит — 120 запросов/минуту на аккаунт, включая все его ключи; до 30 операций записи/минуту. Запросы с корректным ключом считаются и при бизнес-ошибках. Время последнего использования обновляется не чаще раза в минуту. Создание ключей ограничено 10 попытками за 10 минут.

Автоматический повтор POST не предусмотрен: при обрыве соединения результат записи может быть неизвестен. Сначала проверьте список/состояние; не повторяйте переключение `favorite` без проверки. GET и PUT/DELETE избранного можно повторять с задержкой. Бизнес-операции и отзыв ключа сериализуются транзакцией; актуальность ключа проверяется повторно перед выполнением операции.

## Эксплуатация

Миграция `004_api_keys.sql` создаёт таблицу хешей и метаданных ключей; отдельный секрет или почтовый сервис для API не нужен. SQL-миграции выполняются штатным Docker-релизом и GitHub Actions. Устаревшие ключи не дают доступ, даже если их метаданные ещё сохранены. Резервные копии включают таблицу `api_keys`; соблюдайте действующие правила защиты бэкапов. При восстановлении старой БД ранее отозванный ключ может вновь оказаться активным: перед открытием сайта отзовите восстановленные ключи, если состояние отзыва неизвестно.
