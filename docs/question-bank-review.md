# Банк вопросов: изменения 8 октября и проверка 10 октября 2026

Повторный структурный аудит 10 октября проверил исходный банк: 1927 записей, включая 1800 обычных вопросов
(1301 с выбором, 499 числовых) и 127 заданий на кодинг. Для каждого из 18
модулей остаётся 100 обычных вопросов и 6 профильных задач смешанных частей.
Всего 127 кодовых задач включают 108 задач смешанных частей и 19 прежних
практик; 10 прежних практик архивированы и не входят в новые рабочие пулы.
Это численность файлов исходного банка, а не снимок пользовательской базы:
сохранённые в PostgreSQL версии мейнтейнеров могут дополнять или переопределять
эти записи. В 127 задачах задано 408 проверок результата.

## Выполненные изменения 8 октября

- Все 1301 правильных ответа стояли первыми. Позиции теперь сбалансированы
  отдельно внутри каждого модуля; количество ответов A/B/C/D отличается
  максимум на один. Порядок зафиксирован, ключ переставляется вместе с текстом.
- HTML/CSS/React больше не проверяются наличием строк. Проверяются элементы,
  связь label/input, принадлежность форме, порядок и вложенность списков,
  свойства CSS и применимость media query. Комментарий с готовым ответом,
  неверный селектор, отключённое поле или переставленные li проверку не проходят.
  Для HTML/CSS это проверка заданных структурных правил, а не визуальное
  сравнение произвольной страницы в браузере.
- React-задачи на динамические данные получают JSON props из stdin. Проверяются
  пустой и непустой ввод, фильтрация, порядок групп и вложенное дерево.
- Дополнены проверки кодинга: пустые данные, границы, отрицательные значения,
  повторяющиеся рёбра и интервалы, равные расстояния, нулевые дисперсии,
  ключи `__proto__`/`constructor`, строки без завершающего перевода строки.
- Математически целые JSON-числа, например `18.0`, принимаются в задаче
  классификации возраста; boolean, null и строки не принимаются.
- Исправлены две синтаксические ошибки в проверочных эталонных программах:
  bootstrap и пороговая классификация. Они не меняли ключи заданий, но мешали
  проверить их исполнением.
- JSON-ответы старых задач сравниваются по значению. Разница в пробелах и порядке
  ключей объекта не считается ошибкой. Задача с ровно двумя десятичными знаками
  сохраняет проверку текстового формата.
- 54 копии общих задач заменены профильными задачами Backend/API, автоматизации,
  ML Engineering и шести интеграционных модулей. Проверены теги навыков;
  интеграционные задачи покрывают все обязательные навыки своей роли.
- 10 старых отдельных практик, не соответствовавших навыку/интеграционной роли,
  переведены в архив. Новые смешанные части используют профильные задачи.
- Уточнены условия: стиль CSS-рамки, исключение terminating Pod из лимита
  rolling update, импорт itertools, ограничения min-content для Grid,
  тип required input и точная арифметика для инварианта суммы.
- Сохранение вопроса отклоняет пустой ключ, некорректный JSON-ключ,
  неизвестное правило сравнения, неверный язык структурного правила и
  пустую проверку `contains`. Ввод/ключ проверки не обрезаются незаметно.

Стиль CSS-рамки влияет на используемую ширину:
[W3C CSS Backgrounds and Borders](https://www.w3.org/TR/css-backgrounds-3/).
Terminating Pod могут повышать общее число Pod сверх replicas + maxSurge:
[Kubernetes Deployment](https://kubernetes.io/docs/concepts/workloads/controllers/deployment/).
HTML разбирается [parse5](https://parse5.js.org/), CSS —
[PostCSS](https://postcss.org/api/).

## Воспроизводимость

Исправленные экземпляры имеют новые версии и запись в истории. ID остаются
стабильными; для существенно заменённых задач указаны новые узкие семейства.
Текущая локальная версия создаёт суточный пул
`daily-pool-YYYY-MM-DD-mixed-v6-coding-difficulty` с отметкой
`bankRevision: 2026-10-08` и оцениванием `rasch-theory-practice-v3`.
Ревизия `mixed-v3-reviewed-bank` относится к этапу ревью 8 октября и не является
текущим ID. Новый ID используется новыми попытками после обновления. Уже опубликованные
пулы предыдущей версии, начатые попытки и прошлые результаты не переписываются.
Изменения мейнтейнера внутри этой ревизии попадают в следующий суточный пул.

## Проверки

`npm run bank:audit` проверяет структуру всего банка, численность, ключи,
баланс позиций, примеры, семейства и покрытие навыков.
`CODE_SANDBOX_TESTS=1 npm run bank:audit` дополнительно выполняет эталонные
решения всех 127 задач, включая архивные, в изолированной Docker-песочнице
по 408 заданным проверкам.
Эталонные программы не передаются в кандидатский интерфейс.

Последний структурный запуск 10 октября завершился успешно и вывел
`questions: 1927`, `ordinary: 1800`, `choice: 1301`, `numeric: 499`,
`coding: 127`, `retired: 10`, `checks: 408`. Этот запуск **не исполнял код
в Docker**: число `checks` обозначает количество проверок в данных банка,
а не число успешно выполненных контейнерных запусков. Для полного
исполнения нужны доступный Docker и заранее собранный образ, как описано
в [coding-and-role-grades.md](coding-and-role-grades.md).

Отдельные тесты независимо исполняют условия 45 Python- и 63 JavaScript-вопросов
и сверяют результат с ключом. Проверки против обхода используют неверную
разметку, комментарии, CSS-переопределения и константный React-компонент.
Также проверяются неизменность старого пула, новая версия банка, адаптивная
сборка и сохранение результатов.

Ревью и исполнение проверяют корректность задач и механики проверки.
Статистическая сопоставимость сложности и порогов грейдов по реальным
кандидатам этим не устанавливается. Это инженерное ревью и автоматические
проверки, а не независимая предметная экспертиза всех заданий. Текущие
предварительные шкалы v3 описаны в [scoring.md](scoring.md), результаты
симулятора и ограничения — в [grade-hardening.md](grade-hardening.md).

## Добавление проверок в админке

Каждая проверка содержит текстовый `stdin` и boolean `public`; ровно один
открытый пример рекомендуется для смешанных частей. Для обычного вывода
укажите текстовый `expected`; для JSON добавьте `comparison: "json"`.
Для React/HTML-структуры используйте `markupRule: "dom"` и ожидаемый HTML
в `expected`. Для динамического React `stdin` — JSON props, остальные
проверки должны содержать другие props.

HTML-правила: `search-field`, `search-label`, `search-submit`, `plan-title`,
`plan-basic`, `plan-pro`, `registration-email`, `registration-password`,
`registration-submit`. CSS-правила: `toolbar-display`, `toolbar-gap`,
`toolbar-align`, `cards-display`, `cards-columns`, `cards-gap`,
`layout-wide`, `layout-narrow`. Эти именованные правила проверяют требования
задач исходного банка; для другой задачи требуется собственное правило
или проверка ожидаемой HTML-структуры. Наличие произвольной строки больше
не используется для допуска новых заданий.
