# Требования ФСП и состояние реализации

Актуализация: 11 октября 2026 года. Канонический реестр всех обязательных и дополнительных пунктов ТЗ, без презентации: [матрица соответствия](tz-compliance.md).

[Сопроводительная документация](submission-documentation.md) описывает архитектуру, тестирование, подбор, процедуру собственной валидации, ФСП, API, точные версии и воспроизводимый запуск. [PDF для сдачи](submission-documentation.pdf) содержит технический документ для экспертов; внутренняя матрица в PDF не включается.

Матрица различает реализацию функции, наблюдённые измерения и состояние выпуска. Реальный API ФСП не предоставлен организатором; ручное резюме допустимо вместо PDF-распознавания; эталон команды и синтетическая процедура валидации разрешены. Независимая человеческая калибровка повышает доказательность, но не объявляется отсутствующим обязательным модулем.

Дополнительные критерии включены: вакансии/отклики, периодические короткие задания, свежая практика, мобильная версия и проработанные концепции ATS/антифрода. Внешние ATS и корпоративная верификация описаны как концепции в объёме, ожидаемом ТЗ.

Исходное ТЗ сохранено в [source](source/README.md). Результаты исторических экспериментов не переписываются: [валидация](validation.md), [синтетика](synthetic-validation.md), [v3](grade-hardening.md), [текущий продукт JSON](current-product-validation.json), [текущий matching JSON](matching-current-validation.json). Точный production-релиз проверяется по `/api/health`, а не дате документа или локальному изменению.
