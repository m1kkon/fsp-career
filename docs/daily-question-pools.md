# Суточные пулы вопросов

Актуально для версии исходников на 10 октября 2026. Реализация: [`assessments.mjs`](../lib/assessments.mjs), [`daily-pool-scheduler.mjs`](../lib/daily-pool-scheduler.mjs).

| Снимок | Текущая версия |
|---|---|
| ID пула | `daily-pool-YYYY-MM-DD-mixed-v6-coding-difficulty` |
| Ревизия исходного банка (`bankRevision`) | `2026-10-08` |
| Версия оценивания (`scoringRevision`) | `rasch-theory-practice-v3` |
| Стандартная спецификация | v8; при обновлении старой сохранённой спецификации создаётся версия не ниже v9 |
| Модуль | 32 зачётных задания: 28 обычных и 4 задачи кодинга |
| Время по умолчанию | 20 секунд на обычный вопрос, 300 секунд на кодинг; 1760 секунд на зачётную часть модуля |

Эти версии независимы: изменение политики оценивания создаёт новый ID пула, даже если содержательная ревизия банка не менялась. Нестандартные пороги мейнтейнера при обновлении спецификации сохраняются. [Формулы и требования грейдов](scoring.md) и [состав ролей](coding-and-role-grades.md) описаны отдельно.

Кандидат выбирает навык или роль и сразу открывает страницу начала теста. Календаря и предварительной записи нет. Для роли грейд выбирается на этой странице. Попытка и первый таймер создаются только после нажатия «Начать тест» и принятия правил.

Общий пул действует ровно 24 часа: с 00:00 до 00:00 по Москве (UTC+3). Его ID содержит дату и версию формата (`-mixed-v6-coding-difficulty`). При публикации исправленной версии банка создаётся новый пул этой даты для новых попыток; предыдущий остаётся доступен начатым попыткам. Серверный планировщик создаёт текущий пул при запуске приложения и следующий в полночь. Если приложение было выключено или создание не удалось, подготовка/запуск теста создаст недостающий текущий пул. При ошибке планировщик повторяет попытку через минуту.

Пул содержит сохранённые экземпляры вопросов для всех 18 модулей, актуальные версии спецификаций, зачётность, правила времени и версию оценивания `rasch-theory-practice-v3`. Сборка учитывает компетенции, сложности, обе адаптивные ветки, форматы и историю показов. Новые вопросы во время прохождения не генерируются. Обычные экспериментальные вопросы добавляются отдельно, по одной позиции при наличии в модуле; они не заменяют зачётную часть и добавляют время одного обычного вопроса. Экспериментальные задачи кодинга автоматически в суточный пул не добавляются.

Запись пула в PostgreSQL выполняется только при отсутствии его ID. Одновременные запросы получают один сохранённый снимок. Изменения банка и спецификаций в течение дня применяются к будущим пулам, а не к текущему.

При старте сервер самостоятельно выбирает сегодняшний пул и фиксирует все модули, первую часть, обе возможные ветки второй части с двумя заданиями кодинга в каждой части. Повышенная ветка требует ≥65 по шкале маршрутизации и полностью решённой задачи кодинга первой части; иначе выбирается базовая. У каждого кандидата свой вариант по общей спецификации, но уникальность вариантов разных людей не гарантируется. Перезагрузка и повторный запрос запуска восстанавливают активную попытку.

Смена дня не закрывает начатую попытку, не меняет вопросы и не блокирует следующий модуль роли. Каждый открытый вопрос продолжает использовать собственный таймер. Новый тест использует новый пул дня.

Мейнтейнеры видят автоматически созданные суточные пулы в админке. Старые сессии, записи и результаты сохранены; прежние API записи/запуска по регистрации остаются для совместимости. Новый интерфейс не создаёт предварительные записи и отправляет действия `assessment-prepare` и `assessment-start` с `targetId` через `POST /api/action`. Для роли при старте также передаётся `targetGrade`; версия выбранного пула сохраняется в попытке. Контракты описаны в [api.md](api.md).

Таймер планировщика действует внутри процесса приложения; это не внешняя очередь заданий. На нескольких экземплярах единство пула обеспечивает вставка по неизменяемому ID в PostgreSQL. Здоровье базы проверяется через `/api/health`, но этот endpoint сам по себе не подтверждает наличие рабочего Docker-исполнителя для кодинга.
