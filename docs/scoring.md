# Оценивание MVP, версия 1

Новые попытки используют `rasch-theory-practice-v1`, спецификации по умолчанию v6 и пул `mixed-v4-evidence-scoring`. Сохранённые старые спецификации получают новую версию для будущих пулов. Снимки начатых попыток и завершённые результаты не изменяются.

Это предварительная модель продукта. Она устраняет зависимость балла от знаменателя ветки и вводит обязательное практическое подтверждение. Порогам грейдов и числовым параметрам сложности ещё нужна эмпирическая проверка. Балл не является официальным SAT-баллом или доказанной оценкой квалификации рынка труда.

## Теория: общая шкала

В итог входят только зачётные обычные вопросы обеих частей. Ответ оценивается как 0 или 1. Для сложности 1/2/3 спецификация фиксирует якоря b = −1/0/1.

Для фактически предъявленного набора вопросов численно решается уравнение:

`Σ logistic(θ − bᵢ) = число правильных ответов`, где `logistic(x) = 1 / (1 + exp(−x))`.

Балл теории: `100 × logistic(θ)`. При всех ошибках — 0, при всех правильных ответах — 100, что соответствует предельным оценкам θ. Если теоретических вопросов нет, балл — 0.

Название ветки не входит в формулу. Учитывается набор сложностей реально предъявленных вопросов. При одинаковой модельной способности ожидаемые ответы на лёгком и трудном наборах дают один и тот же балл. Это свойство модели, а не заявление об эмпирической эквивалентности экземпляров банка: вопросы одной категории пока имеют одинаковые якоря. При фиксированном наборе сложностей одинаковое количество правильных ответов даёт одинаковый балл, независимо от того, какие именно вопросы решены.

## Кодинг: частичный зачёт

Кредит каждой задачи: `passed / total` по лучшей проверенной сервером отправке. Балл кодинга — 100 × среднее кредитов всех четырёх зачётных задач; пропущенная или не отправленная задача имеет кредит 0. Каждая задача имеет одинаковый вес независимо от числа проверок. Например, 4/5 проверок даёт 80% за задачу вместо прежнего нуля. Черновик и результат «Запустить» не оцениваются.

Количество пройденных проверок должно быть целым от 0 до total, total должен совпадать со снимком проверок задачи, отправка должна иметь серверный `judged: true`. Ключи и закрытые проверки остаются на сервере. Поддерживается старый доверенный бинарный снимок судьи без счётчиков.

## Итог и грейды

`Итог = 0,6 × теория + 0,4 × кодинг`.

Отображается один знак после запятой. Порог проверяется по неокруглённому баллу; используется только технический допуск 1e−9 для погрешности вычислений. Экспериментальные вопросы не входят ни в балл, ни в требования к полностью решённым задачам.

| Грейд | Общий балл по умолчанию | Минимум кодинга | Полностью решённая задача |
|---|---:|---:|---|
| Junior | 50 | 40% | хотя бы одна сложности ≥1 |
| Middle | 70 | 60% | хотя бы одна сложности ≥2 |
| Senior | 90 | 80% | хотя бы одна сложности ≥3 |

Для «+» общий порог — середина между порогом грейда и следующего (для Senior — середина до 100): по умолчанию 60/80/95. Минимум кодинга для Junior+/Middle+/Senior+ — 60%/80%/90%, требование к полностью решённой задаче сохраняется. Общие пороги настраиваются в спецификации; веса и практические требования этой версии фиксированы.

Примеры при полностью правильной теории:

- Все четыре задачи кодинга пропущены: 60/100, квалификация не подтверждена.
- Задачи решены на 100%, 80%, 0%, 0%: кодинг 45%, итог 78, подтверждён Junior, Middle не подтверждён по практике.
- Все задачи решены на 80%: кодинг 80%, итог 92, грейд не подтверждён, поскольку нет полностью решённой задачи.
- Кодинг 100%, 100%, 80%, 80%, полностью решены только задачи сложности 2: итог 96, подтверждён Middle+, Senior не подтверждён без полностью решённой задачи сложности 3.

## Адаптивная часть и роль

Правило `two-stage-16-mixed-coding-v3`: первая часть сохраняет 16 заданий. Для маршрутизации используется та же логистическая шкала с якорями сложности, включая дробные кредиты кодинга. Это предварительное расширение модели для дробных ответов. При балле ≥65 открывается повышенная ветка. Обычный ответ, экспериментальные вопросы и лимиты времени сохраняют прежнее поведение. Обе возможные ветки зафиксированы до старта.

В первой части две задачи кодинга сложности 2, в базовой второй — две сложности 1, в повышенной — две сложности 3. Поэтому Senior требует повышенной ветки и полностью решённой сложной задачи, а не только высокого агрегированного балла.

Правило роли `target-grade-five-outcomes-evidence-v3`: все обычные модули и интеграционный блок должны выполнить требования общего балла и кодинга. Сильный модуль не компенсирует слабый. «Potential higher» появляется только при достижении всех требований следующего грейда. Возможны прежние пять исходов. Результаты модулей роли раскрываются только после окончания всей попытки; незавершённая роль не получает грейд.

## Воспроизводимость и проверки

Спецификация сохраняет якоря, веса, общие пороги, минимумы кодинга и версию правила. Вариант сохраняет версии вопросов, зачётность и ответы. Результат сохраняет общий балл до и после округления, компоненты, количество полностью решённых задач по сложности и основания выполнения каждого грейда и «+». В отчёте показаны компоненты и недостающие условия следующего грейда.

Старые попытки продолжают считать результат по своему правилу: бинарному, `difficulty-weighted-fixed-scale-v1`, старому смешанному v2 и старым правилам роли. Архивные оценки не пересчитываются.

Тесты проверяют общую шкалу на различных наборах сложностей, монотонность, независимость от названия ветки, частичный зачёт, обязательную практику, округление, экспериментальные вопросы, маршрутизацию и сохранение старых правил. Интеграционный тест проходит всю роль с правильной теорией и пропущенным кодингом, проверяя отсутствие квалификации и верификации профиля.
