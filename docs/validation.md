# Валидация MVP

## Проверенная логика

`node --test tests/service.test.mjs` проверяет бизнес-сервис с независимыми аккаунтами кандидата, работодателя и посторонней компании. Тестовый репозиторий моделирует операции хранения; браузерная проверка дополнительно проходит настоящий API и локальную D1.

19 сценариев проходят: контакт отсутствует до согласия и открыт только нужной компании; терминальный ответ не изменяется; неверная зарплата отклоняется; кандидат не выполняет действия работодателя; редактор не подделывает грейд; отзыв согласия исключает профиль; отклик открывает контакт владельцу вакансии; чужая вакансия не редактируется; подмена типа записи отклоняется; тест не раскрывает ключ ответов; неуспешная попытка не снижает категорию; смена ограничена 90 днями; диалог доступен только участникам; запрос ограничивает подтверждённой категорией.

Все 15 комбинаций специализации и грейда имеют 6 вопросов и корректные индексы ответов. Полностью правильный набор получает 100, полностью неправильный — 0. В 50 сгенерированных попытках проверяется более 45 различных комбинаций параметров и вариантов ответа. Это механическая проверка генератора, не оценка дискриминативности.

## Браузерный сценарий

Локальная версия проверена через portable Vinext preview и настоящую D1: регистрация кандидата, заполнение резюме, тест Backend/Middle, присвоение категории, создание компании, подбор, обязательная зарплата, отправка/просмотр/принятие приглашения и раскрытие контакта. Пройден полный цикл вакансии и отклика с ответом компании, задания с ручной обратной связью, диалог и скрытие профиля из каталога. Главная и вакансии проверены при ширине 375 px без горизонтального переполнения. Проверка имеет синтетические данные и не отправляет письма.

## Процедура калибровки для следующего этапа

1. Эксперты размечают компетенции каждого шаблона и ожидаемый грейд, согласуют критерии и фиксируют эталонные объяснения.
2. Набирается пилот из специалистов с независимой экспертной оценкой. Настройка порогов и оценочная выборка разделяются по участникам.
3. Измеряются сложность и дискриминативность вопросов, межэкспертное согласие, повторная стабильность категории на эквивалентных формах, точность по уровням и интервалы неопределённости.
4. Калибруются параметры шаблонов и баланс blueprint, исключаются слабые вопросы; банк версионируется. Часть банка остаётся резервной, раскрываемая обратная связь не содержит готовых ключей резервных заданий.
5. Подбор оценивается по размеченным парам «потребность — кандидат»: precision@k, NDCG и доля приглашений/принятий на отложенном наборе.

Эти эмпирические измерения пока не выполнены. Текущий результат означает корректную работу программных правил, а не доказанную точность определения реального грейда.

Дополнительно проверены публичная выдача опубликованных вакансий без полей владельца, проверка задания только его компанией и отказ сервера при истёкшем тесте. Все страницы обоих кабинетов и публичные страницы проверены при 1280 и 375 px; окна резюме, вакансии и фильтров не выходят за ширину, элементы управления не пересекаются.

Дополнительно проходят 4 проверки ФСП: только fixture-ID и кандидатская роль, отсутствие подделки реестровой проверки/истории через входные поля, отдельная приватность без раскрытия контактов, нормальная работа без истории/после отвязки, безопасная проекция adapter-данных. Эти проверки не доказывают работу настоящего реестра.

Сценарий ФСП дополнительно проверен через браузер и локальную D1: привязка DEMO-FSP-001, отображение истории с меткой тестовых данных, сохранение после перезагрузки, настройки видимости, окно управления и фильтр достижений. При 375 px профиль, настройки, модальное окно и каталог не имеют горизонтального переполнения; фильтр выдаёт только карточки с историей. На desktop сохранены скриншоты профиля и каталога.

Плавность: исследованы код и CSS; нет scroll/wheel-обработчиков, постоянного requestAnimationFrame-цикла или бесконечных анимаций. На главной нет действующего blur/backdrop-filter. В Safari на macOS проверено пролистывание страницы и возвращение к началу; количественный замер FPS/длинных кадров не проводился. По сообщению пользователя превью плавное, неровность Safari слабая. Причина не установлена; исправление не имитируется добавлением искусственного smooth-scroll.

## Экспорт резюме в PDF

`node --test tests/service.test.mjs tests/resume-pdf.test.mjs`: 24/24 проходят. Пять PDF-сценариев проверяют запрет работодателю/отсутствующему аккаунту, собственную контактную проекцию без служебных секретов, канонические demo-достижения и их отдельную видимость, пустой профиль без ложного подтверждения категории, валидный PDF/UTF-8 имя/Cache-Control, длинные кириллические абзацы и неразрывные строки на A4.

Визуальная проверка: обычный пример на одной странице и длинный пример на четырёх страницах отрендерены Poppler. pdfplumber подтверждает сохранение заключительных секций и отсутствие выхода текста за поля. Персональное резюме, предоставленное как образец оформления, не включено в исходники или deployment.
