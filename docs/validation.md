## Базовый запуск проверок

Используйте Node.js ≥22.13.0; CI использует Node.js 24. После установки зависимостей:

```sh
npm run build
npm test
npx tsc --noEmit
npm run lint
npm run bank:audit
```

Сборка создаёт используемый TypeScript манифест клиентских ресурсов. `npm test` запускает `node --test tests/*.test.mjs`. Пропуск проверки нельзя считать подтверждением соответствующей функции. При изменении зависимостей отдельно выполняется `npm audit --omit=dev`; его результат не включён в таблицу выше.

### PostgreSQL

Укажите отдельную базу, имя которой оканчивается на `_test`. Не используйте рабочую базу приложения:

```sh
TEST_DATABASE_URL='postgres://USER:PASSWORD@127.0.0.1:5432/fsp_local_test' npm test
```

Замените заглушки и создайте базу заранее. Фикстуры применяют миграции в случайных схемах, выполняют сценарии и удаляют схемы после проверки. Проверяются JSONB, rollback, конкурентные записи, сессии и почтовые токены, сохранение оценённых попыток, права публичного API и приватность. Без `TEST_DATABASE_URL` соответствующие тесты пропускаются. Исходники фикстур: [tests/helpers/postgres.mjs](../tests/helpers/postgres.mjs), [tests/postgres.test.mjs](../tests/postgres.test.mjs), [tests/assessment-postgres.test.mjs](../tests/assessment-postgres.test.mjs).

### Реальный Docker sandbox

Должны работать Docker и образ с тем же именем, которое использует runner. Для стандартного локального имени:

```sh
docker build -t fsp-code-sandbox:local sandbox
CODE_SANDBOX_TESTS=1 node --test tests/code-runner.test.mjs tests/coding-contract.test.mjs tests/assessments.test.mjs tests/question-bank-review.test.mjs
```

Это включает опциональные проверки исполнения, таймаута и контрактов. Они требуют реального окружения, а не только анализа аргументов Docker. Для полного обхода эталонных решений банка:

```sh
CODE_SANDBOX_TESTS=1 node scripts/question-bank/audit.mjs
```

Настройка отдельного приватного worker и ограничения ресурсов описаны в [coding-and-role-grades.md](coding-and-role-grades.md). Выполненные локальные тесты не заменяют проверку доступности и изоляции production-worker.

### Схемы API

```sh
node scripts/generate-public-api.mjs
node --test tests/api-schema.test.mjs tests/public-api.test.mjs
```

Генератор обновляет публичную OpenAPI-спецификацию; тест актуальности сравнивает её с генератором. PostgreSQL-сценарии публичного API требуют `TEST_DATABASE_URL`. [Контракты и примеры](api.md).

## Синтетическая проверка качества

| Этап | Назначение | Документ и данные |
|---|---|---|
| Исходная реализация → v2 | Исправление минимального грейда, весов опыта, маршрутизации и порогов | [synthetic-validation.md](synthetic-validation.md), [JSON](synthetic-validation-results.json) |
| V2 → текущая v3 | Поправка кодинга на сложность, повторяемость Middle, языковые регрессии опыта | [grade-hardening.md](grade-hardening.md), [JSON](grade-hardening-results.json) |

Текущий повторный прогон: [JSON](current-product-validation.json), sourceHash `ee33f494f9779ac542e7ffb4a854b566fccf8eac347ec6ddb50d984cce833dd8`. На synthetic holdout: 1200 виртуальных профилей, два прохождения, 2400 результатов; совпадение грейда **93,17%**, Middle **86,50%**, повторяемость **87,25%**, завышение **0,67%**. Все пять gates выполнены. Синтетический подбор: 24 потребности, 480 пар, P@5 **97,5%**, допустимость и сумма объяснений **100%**, недопустимых профилей в top-5 **0**.

Виртуальные профили строятся из четырёх авторских прототипов. Разделение ролей/семейств сценариев и форм не создаёт новую популяцию реальных людей: используется та же авторская модель вероятности ответа. Кодинг моделируется доверенными снимками судьи и **не исполняется в sandbox**. Старые проценты v2/v3 сохранены в исторических отчётах, не подменяются текущими. ТЗ допускает собственную синтетическую разметку; человеческая калибровка усилит доказательство, но не объявляется отсутствующим обязательным модулем.

Текущие языковые/matching регрессии: 69 прошли, 0 ошибок, 0 пропусков; в том числе 25 новых языковых случаев. [Реальный текстовый benchmark](matching-current-validation.json): ранее известный holdout 4 вакансии / 102 пары, P@5 35%, TF-IDF 25%, random 23,4%; это воспроизводимость на уже изученной выборке, не новая независимая оценка. Отрицания исправлены без роста агрегатного P@5.
Команды для текущей политики, без изменения пользовательской базы:

```sh
node scripts/benchmarks/synthetic-validation.mjs --label current --split all --output output/validation/synthetic-current
node scripts/benchmarks/harden-grades.mjs --assert --output output/validation/grade-current
node --test tests/synthetic-validation.test.mjs
```

`output/` игнорируется Git. Не перезаписывайте сохранённые `grade-v2`, `grade-v3` и исторический JSON случайным запуском новой политики. Для честного сравнения нужны исходники обеих версий, одинаковая версия benchmark и одинаковые фикстуры; смена подписи `--label` не переключает модель. Инструкции baseline и source hashes — в соответствующих отчётах.
