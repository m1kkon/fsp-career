# ФСП: текущая модель и будущая интеграция

Подключение реального реестра отложено по просьбе пользователя; ФСП не исключена из продукта. По ТЗ API/структура реестра намеренно не предоставляются, поэтому текущая модель использует синтетические данные. Отсутствие достижений не блокирует регистрацию, тест, подбор или приглашение.

## Реализованный демонстрационный сценарий

`lib/fsp.mjs` — серверный mock-adapter без внешних запросов. Принимаются только ID `DEMO-FSP-001`–`DEMO-FSP-014`; остальные отклоняются. Объект `profile.fsp`: `id`, `source: demo`, `status: demo`, `linkedAt`, `achievements`. События содержат синтетический ID, название, дисциплину, год, командный/индивидуальный зачёт, результат, нормализованный уровень (`winner`, `prize`, `final`, `participant`) и источник. У профиля может быть несколько событий. Конкретные даты и подтверждающие ссылки не выдумываются.

`fsp-link`/`fsp-unlink` доступны только своему кандидату; редактор резюме не позволяет подделать источник/достижение. Каталог проецирует только fixture-поля. `fspVisible` отдельно скрывает историю; контакты открываются только компании после принятия/отклика. В карточке, деталях и PDF источник явно тестовый. DEMO-FSP-004/007/008 дают пустую историю, DEMO-FSP-011 — два результата прошлых лет. ID допускают повторное использование разными тестовыми аккаунтами: владение настоящим ФСП ID не подтверждается.

Фильтр наличия достижений реализован. Вклад ФСП в ранг внутри категории — до 10 баллов из 100 (`fspSignal` в `lib/matching.mjs`). Учитывается лучший результат: победа 1, призовое место 0,85, финал 0,6, участие 0,35. Он умножается на профильность дисциплины для нужной специализации (0,7–1) и давность: до двух лет 1, до четырёх 0,75, старше 0,5. Каждое следующее событие добавляет 10%. Сигнал берётся только из канонической проекции адаптера: правка профиля не подделает результат, скрытая история даёт 0. Работодатель видит слагаемое с меткой «Тестовые данные» и разбор по событиям.

## Следующий этап

Будущий серверный adapter принимает FSP ID после согласованной проверки принадлежности аккаунту, например через OAuth/OIDC и будущий Keycloak ФСП. Это предполагаемый подход, не известный контракт; mock-связь автоматически не становится реестровой. Adapter нормализует результат в события: идентификатор соревнования, название, дисциплина, дата, командный/индивидуальный зачёт, место, подтверждающий источник и время проверки. Пока контракт ФСП неизвестен, adapter отделён от продукта; никакие предполагаемые endpoint или структура API не считаются согласованными.

Информация о достижениях хранится отдельно от самоописания резюме, имеет происхождение и статус подтверждения. При недоступности реестра сохраняется последняя успешная проверка с датой и признаком устаревания; отсутствие истории — самостоятельное нормальное состояние. Отзыв разрешения отключает обновление и публикацию спортивной истории.

Фактор ФСП не исключает специалистов без соревнований: без истории доступно 90 баллов из 100, а один вопрос теста весит больше участия или финала. Пороговые веса нужно подтвердить на размеченных парах до работы с реальным реестром. Категория по специализации и грейду остаётся результатом тестирования.

ATS: отдельный экспорт согласованных контактов и статусов после принятия приглашения; webhook с подписью, идемпотентным ключом и аудитом. Верификация работодателей: домен компании, подтверждение владения, сигналы жалоб, лимиты приглашений и очередь модерации. Эти механизмы не включены в MVP.
