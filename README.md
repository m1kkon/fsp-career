# ФСП Карьера

Сервис обратного подбора IT-специалистов. Кандидат заполняет анкету и резюме, подтверждает категорию тестированием и получает предложения. Работодатель описывает потребность, проверяет условия подбора, сравнивает кандидатов и отправляет приглашение с зарплатной вилкой. Контакт открывается конкретной компании после согласия кандидата либо его самостоятельного отклика.

Исходники и результаты проверки актуализированы **11 октября 2026 года**. Установленную production-ревизию показывает [API health](https://fspcareer.space/api/health); наличие коммита и успешного CI не означает завершённый деплой.

## Возможности

- Основной сценарий «Ищу сотрудника» и сценарий «Ищу работу», два кабинета на одном аккаунте. Вход по email/паролю, подтверждение адреса и восстановление пароля через Resend.
- Версионируемая анкета кандидата: специализация, уровень, роли, отрасль, навыки, рабочие предпочтения. Редактор резюме с опытом, образованием, проектами, языками и ссылками; серверный экспорт PDF.
- Профиль компании с описанием, контактами и дополнительной информацией; публикация, редактирование и архивирование вакансий.
- Модульные тесты по 12 навыкам и 6 профессиональным ролям с 6 интеграционными модулями. Теория и кодинг, две адаптивные части, серверные дедлайны, сохранение ответа мышкой или клавиатурой, возобновление попытки и история результатов.
- Подтверждённая категория после полного теста роли; слабая повторная попытка не понижает прежнюю категорию. Паспорт компетенций и рекомендации по результатам теста.
- Разбор запроса работодателя, подтверждение обязательных условий, редактируемые шаблоны навыков, бюджет от–до, контекст команды и объяснение рейтинга. Сравнение до трёх кандидатов, избранное и сохранённые потребности со снимком подборки.
- Приглашения с зарплатой, принятие/отказ; отклики с письмом, статусами и обратной связью. Диалоги участников, короткие задания компаний и ручная обратная связь.
- Согласие, видимость профиля и истории ФСП. Mock-adapter ФСП: тестовая привязка, достижения, отдельная приватность и отвязка.
- Публичный API с отзывными ключами, областями доступа и сроком действия. [Руководство](docs/api.md), [OpenAPI браузерного API](public/openapi.json), [OpenAPI публичного API](public/api-v1.openapi.json).

В исходном наборе **64 синтетических кандидата и 120 синтетических вакансий**. Это демонстрационные сценарии с различающимися навыками, опытом, бюджетом, результатами и историей ФСП; они не являются реальными людьми или актуальными предложениями компаний. Benchmark-профили не загружаются в каталог. Реальные профили появляются после прохождения продуктового сценария и согласия на видимость. Подключение реального реестра ФСП остаётся отдельной задачей.

## Архитектура

| Область | Реализация |
|---|---|
| Оболочка и HTTP API | Next.js 16.3.8, React 19.2.6, Node.js |
| Основной интерфейс | `public/mvp.js`, hash-навигация, отдельный `public/assessments.js`; ресурсы с хешем содержимого |
| Правила продукта | `lib/service.mjs`, роли и приватность на сервере |
| Подбор | `lib/ats.mjs`, `lib/matching.mjs`, `lib/resume-fit.mjs`, `lib/salary-range.mjs` |
| Тестирование | `lib/assessments.mjs`, `lib/adaptive-testing.mjs`, `lib/assessment-scoring.mjs`, банк вопросов |
| Хранение | PostgreSQL 17, JSONB и таблицы авторизации/API-ключей; `lib/postgres.mjs`, миграции `db/migrations/` |
| Исполнение кодинга | Docker sandbox; локальный runner либо отдельный приватный HTTP worker |
| Эксплуатация | Docker Compose: приложение, PostgreSQL, миграции и Caddy; GCP VM, Cloudflare, GitHub Actions |

Исторические файлы Sites/Vinext и пример D1 не задают текущий путь сборки и не заменяют PostgreSQL. `drizzle/` хранит вспомогательные сгенерированные материалы; эксплуатационные миграции применяет `scripts/migrate.mjs` из `db/migrations/`.

Бизнес-записи выполняются транзакционно с advisory lock. Роли, владельцы и статусы проверяются сервером; контакты открываются отдельно каждому работодателю. Пароли хешируются scrypt, сессии используют HttpOnly cookie, токены в базе хешируются. Очередь писем зашифрована; сброс пароля отзывает сессии. Детали: [API](docs/api.md) и [развёртывание](docs/deployment.md).

## Как работает рейтинг

Работодатель подтверждает разобранные требования. Обязательные условия проверяются с исходами `pass`, `unknown`, `fail`; отсутствие данных не считается совпадением. Приоритет этих групп выше числового рейтинга. Бюджет проверяется по пересечению зарплатных диапазонов, включая равенство границ.

Внутри группы рейтинг отражает соответствие **кандидата подтверждённой потребности**. Максимумы: специализация 25, минимальный грейд 15, стек 12, опыт и проекты 20, тест 12, ФСП 6, формат 4, зарплата 4, предметная область 2; всего 100. Подтверждённый Senior соответствует минимуму Middle без штрафа. Балл равен сумме объясняемых слагаемых; диагностический TF-IDF не задаёт отдельный порядок. Без потребности отображается только «Тесты и ФСП» с максимумом 18.

Опыт и проекты сопоставляются правилами извлечения технологий и типов задач. Учитываются отрицания и планы; цитаты показывают основание. Это объяснимый правиловой матчер, а не обученная модель понимания произвольного резюме. Навыки и опыт из резюме остаются заявленными кандидатом данными. [Подробности и benchmark](docs/matching-benchmark.md).

## Локальный запуск

Нужны Node.js **≥22.13.0** (CI использует 24), npm и PostgreSQL 17. Для полноценного кодинга дополнительно нужен Docker или настроенный sandbox worker.

```sh
npm ci --include=dev --include=optional
```

Создайте игнорируемый `.env.local`:

```dotenv
DATABASE_URL=postgres://USER:PASSWORD@127.0.0.1:5432/fsp_local
APP_URL=http://localhost:3000
RESEND_API_KEY=YOUR_SENDING_KEY
EMAIL_FROM=ФСП Карьера <no-reply@YOUR_VERIFIED_DOMAIN>
MAIL_TOKEN_KEY=YOUR_64_HEX_CHARACTERS
```

Замените все заглушки. Почтовые переменные нужны для регистрации и восстановления; домен отправителя должен быть подтверждён. HTTP допустим локально вне production. Для администрирования добавьте `TEST_MAINTAINER_IDS` со списком ID разрешённых аккаунтов; регистрация не выдаёт права администратора.

```sh
node --env-file=.env.local scripts/migrate.mjs
npm run dev
```

Next.js читает `.env.local`; отдельным Node-скриптам нужен `--env-file`. Откройте [localhost:3000](http://localhost:3000). После запроса почтовой ссылки запустите обработчик; это один проход очереди, а не постоянный сервер:

```sh
node --env-file=.env.local scripts/send-mail.mjs
```

Настройка Docker sandbox и рабочего узла: [coding-and-role-grades.md](docs/coding-and-role-grades.md). Без runner/worker выполнение кода недоступно; интерфейс не заменяет серверную проверку.

Для production HTTPS, резервных копий, настройки Resend и автодеплоя используйте [deployment.md](docs/deployment.md). Docker Compose не является конфигурацией обычного локального HTTP-превью.

## Проверки

```sh
npm run build
npm test
npx tsc --noEmit
npm run lint
npm run bank:audit
```

Сборка создаёт манифест клиентских ресурсов; перед отдельной TypeScript-проверкой он должен существовать. Для PostgreSQL-сценариев задайте `TEST_DATABASE_URL` отдельной базы с именем, оканчивающимся на `_test`; тесты создают и удаляют изолированные схемы. Без переменной соответствующие проверки пропускаются. `CODE_SANDBOX_TESTS=1` включает реальные Docker-проверки при наличии собранного образа; инструкции — в [валидации](docs/validation.md).

Проверка GitHub Actions на ревизии `36c4e8e`: **526 тестов прошли, 0 ошибок и 0 пропусков** с PostgreSQL 17 и реальным Docker sandbox. Default production build, TypeScript и ESLint прошли; у ESLint 24 предупреждения, ошибок нет. В конкурентном PostgreSQL-сценарии 100 сохранений 50 аккаунтов завершились за 146 мс во время ожидания judge; это проверка сервисных транзакций, не production HTTP SLA. [Лог CI](https://github.com/m1kkon/fsp-career/actions/runs/38170524774).

Последний полный локальный прогон обновлённой реализации: **499 тестов, 471 прошли, 28 пропущены, 0 ошибок**; Webpack production build, TypeScript и ESLint без ошибок. Пропуски требуют PostgreSQL/Docker; локальные пропуски не являются успехом; указанное выше CI выполнило проверки с сервисами без пропусков.

Структурный аудит: **2359 вопросов, 559 кодовых, 10 выведенных из использования, 2881 заданная проверка**; в указанном CI реально исполнены все **559 эталонных решений/2881 проверка на восьми языках**, все прошли. Локальные и синтетические агрегаты: [JSON](docs/current-product-validation.json), [методика и ограничения](docs/validation.md). Успешный CI не означает публикацию новой версии: установленный релиз определяется `/api/health`.

## Качество и оставшаяся работа

Текущая модель новых попыток — `rasch-theory-practice-v3`: 60% теории и 40% кодинга с поправкой на сложность фактически предъявленных задач. Сырой зачёт кодинга показывается отдельно. Грейд требует общего порога, минимумов теории/практики и полностью решённого задания нужной сложности во всех обязательных модулях. Начатые попытки и старые результаты сохраняют снимки своих правил. [Формулы](docs/scoring.md).

Текущий прогон симулятора на holdout: **1200 виртуальных профилей, два прохождения, 2400 результатов**; совпадение грейда **93,17%**, распознавание Middle **86,50%**, повторяемость **87,25%**, завышение **0,67%**. Контролируемая функциональная регрессия на 24 простых авторских потребностях и 480 парах: первая пятёрка полностью совпадает с эталоном команды (P@5 100%), объяснения проверены на 480/480 парах, допуск совпал с прежней рубрикой на 456/480, недопустимых профилей в top-5 0. Этот набор отражает заложенные правила и не доказывает эмпирическое качество на новых людях. [Доменные регрессии и ограничения абляций](docs/domain-matching-comparison.json). Это авторские прототипы и контролируемые сценарии, не люди и не независимая экспертная калибровка; кодинг симулируется. [Текущий отчёт с хешами](docs/current-product-validation.json), [исторический v3](docs/grade-hardening.md), [исторический v2](docs/synthetic-validation.md).

На одинаковых реальных текстах TalentMatch ранее известного holdout (4 вакансии, 102 пары) текущий blend: **P@5 30%, nDCG@5 0,4704, MRR 0,8750, R@5 39,58%**. TF-IDF: P@5 25%, nDCG@5 0,3366; стек: 30% и 0,4539; случайное ожидание 23,36% и 0,2823. Это частичная проверка текстового ранжирования, без подтверждённых грейдов/тестов/ФСП. [Текущий внешний benchmark](docs/matching-blend-validation.json). На новой авторской диагностике 8/96 текущий метод 42,5%, TF-IDF с теми же фильтрами 47,5%, стек 50%; baseline сильнее. Допуск 96/96 и объяснения 96/96 проверены отдельно от качества ранжирования. [Свежая диагностика и ограничения](docs/domain-challenge-validation.json), [функциональные guards](docs/full-product-matching-guards.json).

Открытые направления: экспертная проверка банка и пилот на людях; разметка реальных пар «потребность — резюме»; расширение проверок отказов окружения; реальный реестр ФСП; внешний ATS и расширение семантического матчера; нагрузочные и эксплуатационные проверки. Состояние пунктов и официальные критерии: [requirements.md](docs/requirements.md).

Сквозная демонстрация: зарегистрировать кандидата и подтвердить email; заполнить анкету/резюме; пройти все модули роли в опубликованной сессии; создать кабинет компании; подтвердить поиск «Middle backend Python PostgreSQL» с бюджетом и задачами команды; изучить объяснение и сравнение; отправить приглашение; принять его кандидатом и проверить раскрытие контакта/диалог. Отдельно показать отклик на собственную вакансию и отзыв согласия на видимость. Демокарточки демонстрируют подбор, но не доставляют предложение реальному человеку.
