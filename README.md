# ФСП Карьера — MVP

Сервис обратного подбора IT-специалистов: кандидат заполняет резюме и подтверждает категорию тестом, работодатель описывает потребность и приглашает конкретного человека с зарплатой от–до. Контакт открывается конкретной компании после согласия кандидата либо его самостоятельного отклика.

## Реализовано

- Главная для кандидатов и отдельная страница для работодателей; каталог вакансий, помощь, описание механики и приватности.
- Подтверждённый вход через ChatGPT/Sites, создание двух ролевых профилей и раздельные кабинеты.
- Резюме: опыт, образование, описание, технологии, город, формат, ожидания и телефон. Стандартизированный PDF через системную печать.
- 12 модулей навыков и 6 ролевых тестов с собственными интеграционными модулями. 1 800 сохранённых зачётных вопросов — по 100 в каждом из 18 модулей, варианты из четырёх ответов и числовой ввод. Запись на сессию, фиксированный пул дня, таймер на каждый вопрос и подтверждение ответа, отдельные результаты навыков и ролей.
- Админка мейнтейнеров: банк/фильтры/карточки, новые вопросы и версии, содержательная проверка, экспериментальный пул, явный допуск или отклонение, версии спецификаций, выбор вопросов и фиксация пулов дня, аналитика качества заданий.
- Подбор по категории, фильтры, сортировка, объяснение балла, избранное, сохранённые потребности.
- Приглашения без обязательной вакансии, зарплатная вилка, просмотр, принятие и отказ. Сервер не передаёт контакт до согласия.
- Публикация, редактирование и архивирование вакансий; отклики с письмом, статусами и обратной связью.
- Диалоги после принятия предложения или самостоятельного отклика.
- Короткие задания компаний, решения кандидатов и ручная обратная связь.
- Настройки согласия, видимости и уведомлений в кабинете.
- Серверная база Cloudflare D1; localStorage хранит только предпочтение кабинета.
- OpenAPI: [public/openapi.json](public/openapi.json). Проверки: [tests/service.test.mjs](tests/service.test.mjs).

Подключение реального реестра ФСП отложено; сама функция остаётся в продукте. Mock-adapter поддерживает тестовый ФСП ID, синтетическую историю, отдельную приватность и отвязку. Достижения показаны в резюме, каталоге, деталях и PDF с меткой «Тестовые данные»; есть фильтр наличия истории. Профили без истории соревнований полностью работоспособны. В каталоге есть 8 явно помеченных синтетических кандидатов и 4 демовакансии. Приглашения этим кандидатам и отклики на демовакансии сохраняются, но не доставляются реальным людям.

## Архитектура

Frontend — vanilla JS с маршрутизацией по hash, адаптивными экранами и формами в `public/mvp.js`, `public/assessments.js` и `public/mvp.css`. Vinext/React отдаёт оболочку страницы и API. Бизнес-правила вынесены в `lib/domain.mjs`, ролевые операции и репозиторий — в `lib/service.mjs`, экзаменационный процесс — в `lib/assessments.mjs`, фиксированный исходный банк и спецификации — в `lib/question-bank.mjs`. D1 содержит `accounts` и `records`: тип записи, владелец, получатель, содержимое и дата. Индексы ограничивают выборки по типу и участникам.

Sites задаёт доступ к сайту и передаёт доверенную идентичность пользователя. Роли создаются в серверной записи аккаунта, а не переключателем браузера. API проверяет роль, владельца/получателя записи и допустимые статусы. Входящие заголовки идентичности должны поступать от Sites, а не из публичного самостоятельно развёрнутого reverse proxy без проверки.

Профиль показывается только при успешном тесте, включённой видимости и согласии. Контакты проецируются отдельно для каждого работодателя. После отзыва согласия новые поиск и приглашения блокируются; уже состоявшиеся взаимодействия остаются в истории.

## Локальный запуск

Нужны Node.js ≥22.13 и npm. Из этого каталога:

```sh
npm ci --include=dev --include=optional --no-audit --no-fund
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_vengeful_old_lace.sql
npm run dev -- --port 4173 --hostname 127.0.0.1
```

Миграцию выполняйте один раз для новой локальной базы. Откройте `http://127.0.0.1:4173`. Кнопка входа в portable preview авторизует синтетический аккаунт `seedy@sites.test`; этот механизм отсутствует в production. Локальная и опубликованная базы независимы.

Проверки:

```sh
node --test tests/*.test.mjs
npx tsc --noEmit
npm run build
```

## Развёртывание

Этот checkout привязан к существующему Sites-проекту; ID сохранён в `.openai/hosting.json`. Manifest использует `d1: "DB"`; static заменён серверной сборкой. Сборка сохраняет интеграцию `sites()` из шаблона. Сгенерированная миграция и Drizzle metadata включаются в исходники и артефакт; Sites применяет миграции при публикации. Используйте source helper и native save/deploy из skill Sites. Не включайте `.wrangler`, `.sites-runtime`, node_modules и секреты в исходники или архив.

## Сквозная демонстрация

1. Войти, создать кабинет кандидата, заполнить резюме.
2. Мейнтейнер создаёт и фиксирует пул будущей сессии. Кандидат выбирает навык или роль, записывается и начинает в окне сессии. Полный успешный ролевой тест подтверждает категорию профиля.
3. Создать второй кабинет компании на том же аккаунте либо использовать другой разрешённый Sites аккаунт.
4. Ввести «Middle backend Python PostgreSQL», сохранить потребность, открыть профиль и отправить приглашение.
5. В кабинете кандидата посмотреть предложение и принять. У работодателя появляется контакт; открывается диалог.
6. Опубликовать свою вакансию, откликнуться как кандидат, ответить на отклик как работодатель.
7. Опубликовать задачу, отправить подход как кандидат и дать обратную связь как работодатель.
8. Выключить согласие в настройках; профиль исчезает из нового поиска.

## Тестирование и админка

Откройте `/#tests` для каталога навыков и ролей, `/#maintainer` для админки. В локальном режиме синтетический аккаунт `local_seedy` имеет доступ мейнтейнера. В production доступ задаётся серверным binding `TEST_MAINTAINER_IDS`: список доверенных user ID через запятую. Поля браузера и выбор кабинета этих прав не выдают.

Исходные вопросы сохранены; банк содержит 1 800 фиксированных зачётных экземпляров — по 100 на каждый из 12 навыковых и 6 интеграционных модулей. Дополнение материализовано в `lib/question-bank-100.mjs` из 504 шаблонов (по три фиксированных экземпляра). Для воспроизводимой офлайн-сборки: `node scripts/question-bank/generate-bank.mjs`. При прохождении вопросы не генерируются. Все вопросы принятого банка доступны для зачётного использования. Новые вопросы через админку сохраняются в черновик и проходят отдельную экспериментальную ветку; допуск — явное решение команды.

Спецификация v3 задаёт **две части по 16 зачётных вопросов**. Первая содержит 5 простых, 6 средних и 5 сложных вопросов. Вторая имеет базовую ветку (8/6/2) и повышенную (2/6/8). Сервер заранее сохраняет обе ветки, но предъявляет только одну: при ≥65% взвешенных баллов первой части — повышенную, иначе базовую. Вес сложности 1/2/3 равен 1/2/3. Экспериментальные ответы не участвуют в выборе ветки. Внутри предъявленных 32 вопросов нет повторов экземпляров или узких семейств. Выбор фиксируется атомарно после первой части и не меняется при перезагрузке. Такой переход между частями следует принципу [Digital SAT](https://satsuite.collegeboard.org/in-school-assessments/sat-school-day/structure); порог и шкала этой платформы — собственные версионированные правила MVP, без заявления о калибровке IRT.

Каждый вопрос получает 20 секунд, модуль — до 10 минут 40 секунд. Экспериментальные позиции добавляются к первой части сверх 16 зачётных и увеличивают длительность на те же 20 секунд каждая. Их может быть ноль. Ограничения числового формата действуют на каждую часть отдельно (по умолчанию 2–8). На экране видны номер части и номер вопроса внутри неё. Вторая часть начинается сразу, промежуточный результат не показывается. Пороги модуля: Junior 50, Middle 70, Senior 90 по фиксированной шкале 0–100.

Опубликованные ранее дни и назначенные попытки сохраняют свои снимки и правила. Новая запись из каталога предлагает адаптивные сессии. Новые дни используют адаптивную спецификацию; старые пользовательские настройки времени и порогов переносятся в новую версию для будущих пулов.

Кандидат может отменить запись до начала теста кнопкой «Отменить запись» и записаться заново. Отмена и начало проверяют состояние записи атомарно; начатая попытка не отменяется через запись.

Мейнтейнер выбирает дату, модули, ожидаемое число участников, конкретные вопросы либо автоматический подбор по спецификациям и частоте показов, число экспериментальных позиций, затем фиксирует пул до начала сессии. Сервер проверяет возможность собрать первую часть и обе ветки второй части. Ролевые тесты используют полные общие модули плюс интеграционный блок; вся последовательность модулей и дерево вариантов назначаются до начала. Варианты соблюдают спецификацию и не повторяют узкие семейства внутри модуля; история показов и частота семейства влияют на выбор. Порядок вопросов и вариантов ответов сохраняется в попытке.

Таймер действует на каждый вопрос в обычных и интеграционных модулях, отдельно и внутри ролевого теста. Выбор варианта остаётся локальным до нажатия «Ответить»; подтверждение сохраняет ответ и открывает следующий вопрос со своим лимитом. «Пропустить» или истечение времени сохраняют пропуск. Закрытые вопросы нельзя открыть повторно или изменить. Перезагрузка восстанавливает тот же вариант и дедлайн текущего вопроса. Сервер закрывает модуль после последнего вопроса. Следующий модуль открывается после регламентного перерыва независимо от результата предыдущего. Во время комплексной попытки баллы модулей не показываются между блоками, в резюме или истории и не передаются через API. Все результаты раскрываются вместе после завершения теста; при досрочном завершении сохраняются результаты закрытых модулей. Начатый модуль нельзя поставить на паузу. Запуск и сохранение защищены от конкурентных запросов.

«Удалить из истории» скрывает завершённую или незавершённую попытку и все её результаты из истории и резюме. Данные остаются в БД, аналитике вопросов и истории показов. Скрытую попытку можно вернуть из свёрнутого раздела «Удалённые из истории». Активную попытку сначала нужно завершить.

Числа проверяются по сохранённому ключу, округлению и погрешности. LLM не оценивает ответы. Для v3 балл — сумма весов правильно решённых зачётных вопросов обеих частей, делённая на фиксированный максимум 70 и умноженная на 100 с округлением. 70 — максимум первой части (32) и повышенной второй (38). Ошибка или пропуск даёт 0, бонуса за скорость нет. В результат сохраняются верные ответы из 32, заработанные/максимальные баллы, выбранная ветка и версия правил. Прежние попытки сохраняют процент правильных ответов по своему правилу. Итог роли требует достижения порога в каждом обязательном модуле и интеграции; среднее не компенсирует провал. Закрытые общие модули ролевой попытки также попадают в историю навыков. Незавершённая роль отмечается отдельно.

Снимки спецификаций, пула, вопросов, ключей, зачётности и ответы хранятся в серверной записи попытки. Новая версия или поздний допуск экспериментального вопроса не изменяет старые оценки. Кандидат получает только условия, варианты и собственные результаты; ключи, разборы и признаки экспериментальных позиций ему не передаются. Старый HTTP-формат экзаменов с выбором грейда отключён, исторические баллы сохранены.

На странице тестов сверху показаны последние завершённые результаты навыков и ролей. Кнопка «Подтвердить квалификацию» открывает выбор навыка/роли и календарь на две недели: доступность определяется опубликованными адаптивными сессиями, полным составом роли и оставшимся временем. Даты и время показаны по Москве; подтверждение создаёт обычную запись на выбранную сессию. Кнопка с глазом скрывает конкретный результат от работодателей и возвращает его повторным нажатием. Результат остаётся владельцу, в БД и аналитике. Навык и роль одной попытки управляются независимо. Скрытый последний результат не заменяется старым в публичной выдаче. Сервер фильтрует результаты в каталоге и откликах; скрытое подтверждение роли также исключает балл и грейд из карточки и подбора работодателя.

## Проверки

89 автоматических проверок покрывают новый банк (100 вопросов на модуль), обе адаптивные ветки и все 18 спецификаций, числовые правила и ключи новых заданий, доступ мейнтейнера, неизменность пулов и попыток, экспериментальную ветку, обязательные пороги роли, сохранение закрытых навыков, таймер и конкурентные запросы, а также прежние функции подбора и приватности. TypeScript и production-сборка проверяются отдельно.

Банк принимается готовым по спецификации MVP. Экспериментальная аналитика служит развитию банка и не блокирует запуск исходных зачётных вопросов.

## Границы текущей версии

- Вход ChatGPT используется для текущего Sites-хостинга. Собственная email-регистрация с подтверждением ещё предстоит; платформенный вход не закрывает это требование.
- ФСП ID и достижения работают на mock-данных; реальный реестр, проверка владения и вклад ФСП в численное ранжирование ещё не реализованы. Нет ATS, PDF-парсинга, исполнения пользовательского кода, верификации компаний, модерации и email-рассылки.
- PDF формируется стандартной печатью браузера; выберите «Сохранить как PDF».
- Короткие задания проверяются компанией вручную. Они не меняют грейд; проверенная обратная связь обновляет актуальность профиля. Автоматического расписания выдачи пока нет.
- Сайт сохраняет приватную аудиторию Sites. Доступ жюри/других пользователей настраивает владелец отдельно.
- Эксплуатация с реальными персональными данными требует юридической и инфраструктурной проверки, включая локализацию хранения. Соответствие 152-ФЗ не заявляется.
