# ФСП Карьера — MVP

Сервис обратного подбора IT-специалистов: кандидат заполняет резюме и подтверждает категорию тестом, работодатель описывает потребность и приглашает конкретного человека с зарплатой от–до. Контакт открывается конкретной компании после согласия кандидата либо его самостоятельного отклика.

## Реализовано

- Главная для кандидатов и отдельная страница для работодателей; каталог вакансий, помощь, описание механики и приватности.
- Временный вход через идентичность Sites, создание двух ролевых профилей и раздельные кабинеты. Собственный выход закрывает кабинет, возвращает на главную и сохраняет профиль; сессия хостинга остаётся открытой. Email-авторизация ещё не реализована.
- Резюме: опыт, образование, описание, технологии, город, формат, ожидания и телефон. Можно сохранять частично заполненный профиль; зарплата необязательна и не подставляется автоматически. Готовый текстовый PDF скачивается из сохранённого профиля без диалога печати. Единый редактор позволяет добавлять/удалять места работы, образование и курсы, группы навыков, проекты и ссылки. Опыт и образование заполняются карточками с отдельными полями и датами; старый текст переносится без потери содержания. Необязательные пустые разделы отсутствуют в PDF.
- Серверное тестирование пяти направлений и трёх уровней: план по грейду, шесть вопросов, перестановка вариантов, параметризованные расчётные задания, проверка на сервере, история, автоматическая категория при успешном результате, интервал смены 90 дней.
- Подбор по категории, фильтры, сортировка, объяснение балла, избранное, сохранённые потребности.
- Приглашения без обязательной вакансии, зарплатная вилка, просмотр, принятие и отказ. Сервер не передаёт контакт до согласия.
- Публикация, редактирование и архивирование вакансий; отклики с письмом, статусами и обратной связью.
- Диалоги после принятия предложения или самостоятельного отклика.
- Короткие задания компаний, решения кандидатов и ручная обратная связь.
- Настройки согласия, видимости и уведомлений в кабинете.
- Серверная база Cloudflare D1; localStorage хранит только предпочтение кабинета.
- OpenAPI: [public/openapi.json](public/openapi.json). Проверки: [tests/service.test.mjs](tests/service.test.mjs).

Подключение реального реестра ФСП отложено; сама функция остаётся в продукте. Mock-adapter поддерживает тестовый ФСП ID, синтетическую историю, отдельную приватность и отвязку. Достижения показаны в резюме, каталоге, деталях и PDF с меткой «Тестовые данные»; есть фильтр наличия истории. Профили без истории соревнований полностью работоспособны. В каталоге есть 8 явно помеченных синтетических кандидатов и 4 демовакансии. Приглашения этим кандидатам и отклики на демовакансии сохраняются, но не доставляются реальным людям.

## Архитектура

Frontend — vanilla JS с маршрутизацией по hash, адаптивными экранами и формами в `public/mvp.js` и `public/mvp.css`. Vinext/React отдаёт оболочку страницы и API. Бизнес-правила вынесены в `lib/domain.mjs`, ролевые операции и репозиторий — в `lib/service.mjs`. D1 содержит `accounts` и `records`: тип записи, владелец, получатель, содержимое и дата. Индексы ограничивают выборки по типу и участникам.

Sites задаёт доступ к сайту и передаёт доверенную идентичность пользователя. Роли создаются в серверной записи аккаунта, а не переключателем браузера. API проверяет роль, владельца/получателя записи и допустимые статусы. Входящие заголовки идентичности должны поступать от Sites, а не из публичного самостоятельно развёрнутого reverse proxy без проверки.

Профиль показывается только при успешном тесте, включённой видимости и согласии. Контакты проецируются отдельно для каждого работодателя. После отзыва согласия новые поиск и приглашения блокируются; уже состоявшиеся взаимодействия остаются в истории.

## Локальный запуск

Нужны Node.js ≥22.13 и npm. Из этого каталога:

```sh
npm ci --include=dev --include=optional --no-audit --no-fund
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_vengeful_old_lace.sql
npm run dev -- --port 4173 --hostname 127.0.0.1
```

Миграцию выполняйте один раз для новой локальной базы. Откройте `http://127.0.0.1:4173`. Кнопка входа в portable preview авторизует синтетический аккаунт `seedy@sites.test`; этот механизм отсутствует в production. Локальная и опубликованная базы независимы.

Проверки:

```sh
node --test tests/service.test.mjs tests/resume-pdf.test.mjs tests/client-requests.test.mjs tests/app-session.test.mjs tests/resume-history.test.mjs tests/client-assets.test.mjs
npx tsc --noEmit
npm run build
```

## Развёртывание

Этот checkout привязан к существующему Sites-проекту; ID сохранён в `.openai/hosting.json`. Manifest использует `d1: "DB"`; static заменён серверной сборкой. Сборка сохраняет интеграцию `sites()` из шаблона. Сгенерированная миграция и Drizzle metadata включаются в исходники и артефакт; Sites применяет миграции при публикации. Используйте source helper и native save/deploy из skill Sites. Не включайте `.wrangler`, `.sites-runtime`, node_modules и секреты в исходники или архив.

## Сквозная демонстрация

1. Войти, создать кабинет кандидата, заполнить резюме.
2. Выбрать специализацию и грейд, успешно пройти тест. Профиль получает категорию и появляется в поиске.
3. Создать второй кабинет компании на том же аккаунте либо использовать другой разрешённый Sites аккаунт.
4. Ввести «Middle backend Python PostgreSQL», сохранить потребность, открыть профиль и отправить приглашение.
5. В кабинете кандидата посмотреть предложение и принять. У работодателя появляется контакт; открывается диалог.
6. Опубликовать свою вакансию, откликнуться как кандидат, ответить на отклик как работодатель.
7. Опубликовать задачу, отправить подход как кандидат и дать обратную связь как работодатель.
8. Выключить согласие в настройках; профиль исчезает из нового поиска.

## Проверка качества

Автоматические проверки покрывают изоляцию контактов, ролевые ограничения, владельцев записей, статусы, обязательную зарплату, отсутствие ключей ответов в API, все 15 планов тестирования, вариативность, непринудительное понижение и cooldown. Результаты и процедура описаны в `docs/validation.md`.

Оценка ранжирования на синтетической выборке проверяет корректность правил, а не качество найма на реальном рынке. Небольшой банк имеет общие концептуальные вопросы между уровнями и два расчётных варианта. Без экспертной разметки нельзя заявлять психометрическую валидность. Расширение банка, пилот с экспертами, IRT/Rasch-калибровка и контроль утечки необходимы перед применением результатов в реальном найме.

## Границы текущей версии

- Вход ChatGPT используется для текущего Sites-хостинга. Собственная email-регистрация с подтверждением ещё предстоит; платформенный вход не закрывает это требование.
- ФСП ID и достижения работают на mock-данных; реальный реестр, проверка владения и вклад ФСП в численное ранжирование ещё не реализованы. Нет ATS, PDF-парсинга, исполнения пользовательского кода, верификации компаний, модерации и email-рассылки.
- PDF формируется сервером из своего сохранённого резюме. Пустые секции скрываются; кириллица, списки и переносы на несколько страниц поддерживаются. Шрифты Liberation Serif встроены, внешнего сервиса генерации нет. Навыки оформляются таблицей, проекты — отдельными блоками с описаниями; контакты и ссылки кликабельны.
- Короткие задания проверяются компанией вручную. Они не меняют грейд; проверенная обратная связь обновляет актуальность профиля. Автоматического расписания выдачи пока нет.
- Сайт сохраняет приватную аудиторию Sites. Доступ жюри/других пользователей настраивает владелец отдельно.
- Эксплуатация с реальными персональными данными требует юридической и инфраструктурной проверки, включая локализацию хранения. Соответствие 152-ФЗ не заявляется.

## Компоненты и версии

Vinext 1.0.0-beta.5, Vite 8.0.13, React/React DOM 19.2.6, Next 16.3.4 (совместимые интерфейсы), Wrangler 4.92.0, TypeScript 5.9.3, Drizzle ORM 0.45.2, Drizzle Kit 0.31.10, pdf-lib 1.17.1, @pdf-lib/fontkit 1.1.1. Точные версии всего starter-окружения зафиксированы `package-lock.json`. Шрифт Golos Text загружается через Google Fonts с системным fallback.

Подробное соответствие исходному ТЗ: [docs/requirements.md](docs/requirements.md). Переходы страниц и вопросов сопровождаются направленной анимацией; таймер теста отсчитывает оставшееся время, а режим reduced motion отключает перемещения.

Клиентские ресурсы версионируются по содержимому при `npm run dev` / `npm run build`; это предотвращает смешивание новых форм со старыми CSS и скриптами из кеша браузера.
